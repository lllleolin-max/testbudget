# Bounded buyer pilot

User/buyer hypothesis: a CI platform engineer or team owning a small set of expensive integration suites, where a fixed PR-run budget forces tradeoffs between smoke coverage, nondeterministic retries and less frequently sampled suites. Launchable's official predictive-selection workflow confirms this is an existing engineering job; it does not validate demand for this project.

Pilot: define <=20 independently runnable suite units, explicit environment labels and maximum retries. Export historical attempt JSON from the runner, use increasing branch-local ordinals, select a frozen plan, execute selected units through the existing runner and record observed attempts. Keep periodic full-suite runs to detect blind spots and independently diagnose failures. Configure smoke/coverage/exploration with CI owners; validate actual durations before enforcing any timeout externally. Start in shadow mode and use plan explanations to inspect selection changes.

Value mechanism: revision collapse prevents repeated flaky retries from dominating a regression proxy; group maxima avoid spending repeatedly on a declared common failure family; exploration rotates in unseen/stale suites at an explicit opportunity cost. Exact constrained comparisons tell a reviewer whether the desired policy fits the declared budget, including a reproducible cheaper-cost frontier. The provided synthetic benchmark measures selection and simulated seconds; it establishes no real monetary saving.

For an illustrative 60 reserved-second full suite with a 20-second plan, declared serial reserve decreases by 40 seconds (67%). If the runner actually follows these estimates and PR volume is 100/day, that corresponds to 4000 serial runner-seconds/day before setup/parallelism/retries/maintenance; neither actual rate nor actual savings is measured here. A missed regression may cost more than all saved compute. Tight-budget adverse fixtures demonstrate that cost. Adoption, revenue, willingness to pay and production reliability are unknown.

Acceptance criteria for a real pilot: record actual duration overruns, independently diagnosed regressions caught/missed, constraint feasibility, full-run blind spots and operational history-store errors for at least a representative release window. Compare constraint-respecting policies on identical data. Reject the pilot if evidence quality, grouping assumptions or exploration opportunity cost are unacceptable. Sustainable scope is the offline schema, bounded solver and trace workflow; no hosted service, CI vendor support SLA or claimed enterprise deployment is supplied.
